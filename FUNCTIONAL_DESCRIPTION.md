# LibraSmart - Функциональное описание системы
## Для построения схем DFD и IDEF0

---

## 1. Общее описание системы

**LibraSmart** - автоматизированная информационная система управления библиотечным фондом и обслуживанием читателей.

### Назначение системы
Система предназначена для автоматизации процессов работы библиотеки:
- Учет библиотечного фонда (книги и их экземпляры)
- Обслуживание читателей (регистрация, выдача, возврат книг)
- Управление несколькими библиотечными филиалами
- Формирование отчетности и статистики

### Границы системы
Система обслуживает:
- **Внешние пользователи (читатели)** - граждане, пользующиеся услугами библиотеки
- **Внутренние пользователи (персонал)** - сотрудники библиотеки разных уровней
- **Администраторы** - управляющий персонал библиотечной сети

---

## 2. Внешние сущности (контекст системы)

### 2.1. Читатель
**Роль:** Основной потребитель библиотечных услуг

**Взаимодействие с системой:**
- Отправляет в систему: данные для регистрации, запросы на поиск книг, заявки на бронирование
- Получает от системы: информацию о книгах, уведомления о статусе бронирований и займов, личную статистику

**Потребности:**
- Найти нужную книгу в каталоге
- Узнать, где книга доступна
- Забронировать книгу
- Узнать о своих текущих займах и задолженностях
- Просмотреть историю чтения

### 2.2. Библиотекарь
**Роль:** Сотрудник, выполняющий операции по обслуживанию читателей

**Взаимодействие с системой:**
- Отправляет в систему: данные о выдаче/возврате книг, информацию о новых читателях, обновления статусов
- Получает от системы: списки активных займов, информацию о просрочках, данные о наличии книг

**Потребности:**
- Зарегистрировать нового читателя
- Выдать книгу читателю
- Принять книгу от читателя
- Обработать бронирование
- Найти информацию о читателе или книге

### 2.3. Администратор
**Роль:** Управляющий персонал библиотечной системы

**Взаимодействие с системой:**
- Отправляет в систему: данные о новых филиалах, информацию о сотрудниках, настройки системы
- Получает от системы: сводную статистику, аналитические отчеты

**Потребности:**
- Управлять персоналом
- Управлять филиалами библиотечной сети
- Получать статистику использования
- Анализировать популярность книг и жанров

## 3. Основные бизнес-процессы

### 3.1. Процесс: Регистрация читателя

**Входные данные:**
- ФИО читателя
- Контактные данные (телефон, email)
- Пароль для входа

**Последовательность действий:**
1. Читатель предоставляет личные данные
2. Система проверяет уникальность email
3. Система создает учетную запись читателя
4. Система сохраняет данные в хранилище читателей

**Выходные данные:**
- Подтверждение регистрации
- Идентификатор читателя

**Результат:** Читатель зарегистрирован в системе и может пользоваться услугами

---

### 3.2. Процесс: Поиск и просмотр книг

**Входные данные:**
- Поисковый запрос (название, автор, жанр)
- Фильтры (жанр, год издания)

**Последовательность действий:**
1. Читатель формирует поисковый запрос
2. Система обращается к каталогу книг
3. Система фильтрует результаты по критериям
4. Система проверяет наличие экземпляров в библиотеках
5. Система предоставляет список найденных книг с информацией о наличии

**Выходные данные:**
- Список книг с описаниями
- Информация о наличии в разных филиалах
- Статус доступности экземпляров

**Результат:** Читатель получает информацию о доступных книгах

---

### 3.3. Процесс: Бронирование книги

**Входные данные:**
- Идентификатор читателя
- Идентификатор книги
- Идентификатор библиотеки (филиала)

**Последовательность действий:**
1. Читатель выбирает книгу и библиотеку
2. Система проверяет наличие доступных экземпляров
3. Система проверяет отсутствие активных бронирований у читателя на эту книгу
4. Система создает запись о бронировании
5. Система обновляет статус экземпляра на "забронирован"

**Выходные данные:**
- Подтверждение бронирования
- Номер бронирования
- Срок действия бронирования

**Результат:** Книга зарезервирована для читателя в выбранном филиале

---

### 3.4. Процесс: Выдача книги читателю

**Входные данные:**
- Идентификатор читателя
- Идентификатор экземпляра книги
- Идентификатор библиотекаря
- Срок возврата

**Последовательность действий:**
1. Библиотекарь выбирает читателя
2. Библиотекарь выбирает экземпляр книги
3. Система проверяет доступность экземпляра
4. Система устанавливает срок возврата
5. Система создает запись о займе (выдаче)
6. Система обновляет статус экземпляра на "выдана"
7. Если была активная бронь - система отменяет бронирование

**Выходные данные:**
- Подтверждение выдачи
- Номер займа
- Дата возврата

**Результат:** Книга выдана читателю, создана запись о займе

---

### 3.5. Процесс: Возврат книги

**Входные данные:**
- Идентификатор займа
- Фактическая дата возврата

**Последовательность действий:**
1. Библиотекарь находит активный займ
2. Система фиксирует дату возврата
3. Система проверяет наличие просрочки
4. Система обновляет статус займа на "возвращена"
5. Система обновляет статус экземпляра на "доступна"

**Выходные данные:**
- Подтверждение возврата
- Информация о просрочке (если есть)

**Результат:** Книга возвращена, экземпляр снова доступен для выдачи

---

### 3.6. Процесс: Управление библиотечным фондом

**Входные данные:**
- Информация о книге (название, автор, ISBN, жанр, год издания)
- Информация об экземплярах (инвентарный номер, филиал)

**Последовательность действий:**
1. Библиотекарь вносит данные о новой книге
2. Система проверяет уникальность записи
3. Система сохраняет книгу в каталог
4. Библиотекарь добавляет физические экземпляры
5. Система привязывает экземпляры к филиалам
6. Система устанавливает статус экземпляров "доступна"

**Выходные данные:**
- Подтверждение добавления книги
- Список созданных экземпляров

**Результат:** Новая книга и ее экземпляры добавлены в систему

---

### 3.7. Процесс: Формирование статистики

**Входные данные:**
- Период анализа
- Фильтры (филиал, жанр)

**Последовательность действий:**
1. Администратор запрашивает статистику
2. Система обращается к хранилищу займов
3. Система агрегирует данные по критериям
4. Система анализирует популярность книг и жанров
5. Система выявляет активных читателей
6. Система формирует отчет

**Выходные данные:**
- Количество активных читателей
- Количество выданных книг
- Количество просрочек
- Топ популярных книг
- Топ популярных жанров
- Самые активные читатели

**Результат:** Получена аналитическая информация для принятия управленческих решений

## 4. Хранилища данных

### 4.1. Хранилище "Читатели"
**Содержит:**
- Личные данные читателей
- Контактную информацию
- Учетные данные для входа
- Дату регистрации

### 4.2. Хранилище "Каталог книг"
**Содержит:**
- Библиографические данные книг
- Связь с жанрами
- Информацию об авторах
- ISBN и годы издания

### 4.3. Хранилище "Экземпляры книг"
**Содержит:**
- Инвентарные номера
- Привязку к филиалам
- Текущий статус (доступна, выдана, забронирована)
- Связь с книгами из каталога

### 4.4. Хранилище "Бронирования"
**Содержит:**
- Связь читатель-книга-филиал
- Дату создания брони
- Статус бронирования (активна, выполнена, отменена)

### 4.5. Хранилище "Займы"
**Содержит:**
- Связь читатель-экземпляр-библиотекарь
- Дату выдачи
- Плановую дату возврата
- Фактическую дату возврата
- Статус (активна, возвращена, просрочена)

### 4.6. Хранилище "Персонал"
**Содержит:**
- Личные данные сотрудников
- Роли и права доступа
- Привязку к филиалам
- Учетные данные для входа

### 4.7. Хранилище "Библиотеки"
**Содержит:**
- Названия филиалов
- Адреса
- Контактную информацию
- Режим работы

### 4.8. Хранилище "Жанры"
**Содержит:**
- Названия жанров
- Описания жанров

## 5. Потоки данных

### 5.1. Основные потоки данных в системе

#### Регистрация и авторизация
- **Читатель → Система:** Регистрационные данные
- **Система → Хранилище читателей:** Новая учетная запись
- **Читатель → Система:** Логин и пароль
- **Система → Читатель:** Подтверждение входа, идентификатор сессии

#### Работа с каталогом
- **Читатель → Система:** Поисковый запрос
- **Система → Каталог книг:** Запрос на выборку
- **Каталог книг → Система:** Список книг
- **Система → Хранилище экземпляров:** Запрос наличия
- **Хранилище экземпляров → Система:** Информация о доступности
- **Система → Читатель:** Результаты поиска с наличием

#### Бронирование
- **Читатель → Система:** Запрос на бронирование
- **Система → Хранилище бронирований:** Проверка дублей
- **Система → Хранилище экземпляров:** Проверка доступности
- **Система → Хранилище бронирований:** Создание брони
- **Система → Хранилище экземпляров:** Обновление статуса
- **Система → Читатель:** Подтверждение бронирования

#### Выдача книги
- **Библиотекарь → Система:** Данные о выдаче
- **Система → Хранилище экземпляров:** Проверка доступности
- **Система → Хранилище займов:** Создание займа
- **Система → Хранилище экземпляров:** Обновление статуса
- **Система → Хранилище бронирований:** Отмена брони (если была)
- **Система → Библиотекарь:** Подтверждение выдачи

#### Возврат книги
- **Библиотекарь → Система:** Данные о возврате
- **Система → Хранилище займов:** Обновление записи займа
- **Система → Хранилище экземпляров:** Обновление статуса
- **Система → Библиотекарь:** Подтверждение возврата, информация о просрочке

#### Статистика
- **Администратор → Система:** Запрос статистики
- **Система → Хранилище займов:** Выборка данных за период
- **Система → Хранилище читателей:** Подсчет активных
- **Система → Хранилище книг:** Анализ популярности
- **Система → Администратор:** Сводный отчет

**Функция:** Управление библиотечным фондом и обслуживание читателей

**Входы:**
- Запросы читателей
- Команды персонала
- Административные решения

**Выходы:**
- Информация о книгах
- Подтверждения операций
- Отчеты и статистика

**Управление:**
- Правила библиотечного обслуживания
- Сроки выдачи книг
- Права доступа персонала

**Механизмы:**
- Программное обеспечение системы
- База данных
- Сетевая инфраструктура

---

## 7. Правила и ограничения

### 7.1. Бизнес-правила
- Читатель может иметь только одно активное бронирование на одну и ту же книгу
- Экземпляр книги не может быть выдан, если он уже выдан другому читателю
- При возврате книги позже установленного срока фиксируется просрочка
- Только администраторы могут управлять персоналом
- Бронирование автоматически отменяется при выдаче книги

### 7.2. Технические ограничения
- Email читателя должен быть уникальным в системе
- Email сотрудника должен быть уникальным в системе
- У каждого экземпляра должен быть уникальный инвентарный номер
- Экземпляр должен быть привязан к конкретному филиалу

### 7.3. Статусы и их переходы

#### Статусы экземпляра:
- **Доступна** → Выдана (при выдаче)
- **Доступна** → Забронирована (при бронировании)
- **Забронирована** → Выдана (при выдаче по брони)
- **Забронирована** → Доступна (при отмене бронирования)
- **Выдана** → Доступна (при возврате)

#### Статусы займа:
- **Активна** (книга у читателя, срок не истек)
- **Просрочена** (книга у читателя, срок истек)
- **Возвращена** (книга возвращена)

#### Статусы бронирования:
- **Активна** (бронирование действует)
- **Выполнена** (книга выдана по бронированию)
- **Отменена** (бронирование отменено)

## 8. Роли и права доступа

### 8.1. Читатель
**Доступные функции:**
- Регистрация и вход в систему
- Поиск и просмотр каталога
- Бронирование книг
- Просмотр своих займов
- Просмотр истории чтения
- Управление своим профилем

**Ограничения:**
- Не может видеть данные других читателей
- Не может изменять каталог
- Не может управлять займами напрямую

### 8.2. Библиотекарь
**Доступные функции:**
- Все функции читателя +
- Управление читателями (создание, редактирование, просмотр)
- Управление каталогом книг
- Управление экземплярами
- Выдача и возврат книг
- Управление бронированиями
- Просмотр статистики

**Ограничения:**
- Не может управлять персоналом
- Не может удалять библиотеки

### 8.3. Администратор
**Доступные функции:**
- Все функции библиотекаря +
- Управление персоналом (добавление, редактирование, удаление сотрудников)
- Управление библиотечной сетью (филиалы)
- Доступ ко всей статистике и отчетности

**Ограничения:**
- Нет (полный доступ)

## 9. Сценарии использования

### Сценарий 1: Читатель берет книгу
1. Читатель заходит в систему
2. Читатель ищет книгу в каталоге
3. Читатель просматривает наличие в филиалах
4. Читатель создает бронирование в удобном филиале
5. Читатель приходит в библиотеку
6. Библиотекарь находит бронирование
7. Библиотекарь выдает книгу читателю
8. Система фиксирует выдачу и отменяет бронирование

### Сценарий 2: Библиотекарь пополняет фонд
1. Библиотекарь получает новые книги
2. Библиотекарь добавляет информацию о книге в каталог
3. Библиотекарь регистрирует физические экземпляры
4. Библиотекарь указывает филиал для каждого экземпляра
5. Система делает экземпляры доступными для выдачи

### Сценарий 3: Администратор анализирует работу
1. Администратор запрашивает статистику за месяц
2. Система формирует отчет о выдачах
3. Система показывает топ популярных книг
4. Система показывает активных читателей
5. Администратор принимает решения о закупке новых книг

## 10. Словарь терминов

**Читатель** - физическое лицо, зарегистрированное в системе для пользования библиотечными услугами

**Книга** - библиографическая единица в каталоге (абстрактное понятие)

**Экземпляр** - конкретная физическая копия книги с инвентарным номером

**Бронирование** - резервирование экземпляра книги для конкретного читателя

**Займ (Выдача)** - факт передачи экземпляра книги читателю на определенный срок

**Филиал (Библиотека)** - физическое местоположение библиотечного фонда

**Жанр** - категория классификации книг (художественная литература, научная и т.д.)

**Библиотекарь** - сотрудник, выполняющий операции обслуживания читателей

**Администратор** - сотрудник с правами управления системой и персоналом

**Просрочка** - ситуация, когда книга не возвращена в установленный срок

**Каталог** - систематизированное собрание записей о всех книгах в системе

## 11. Временные характеристики процессов

### Типовые сроки
- **Регистрация читателя:** мгновенно
- **Поиск книги:** мгновенно
- **Создание бронирования:** мгновенно
- **Выдача книги:** 1-2 минуты (время физической выдачи)
- **Возврат книги:** 1-2 минуты (время физического приема)
- **Формирование статистики:** несколько секунд

### Срок действия
- **Бронирование:** обычно 3-7 дней
- **Займ:** обычно 14-30 дней (зависит от типа книги)

- **Одновременные пользователи:** десятки - сотни
